# 原始需求与范围变化

## 原始产品定位

最初 PRD 将产品定义为一款配合线下阿瓦隆使用的移动端记录工具：记录玩家身份、组队、投票和任务结果，并进一步计算嫌疑度、支持赛后复盘与战绩查看。

## 原始 MVP 流程

```text
输入人数
  → 选择阵容
  → 录入玩家昵称
  → 生成规则、笔记与圆桌座位图
  → 逐轮记录组队、投票与任务结果
  → 一方三次任务胜利，或触发连续否决规则
  → 显示结果、保存记录、返回首页
```

## 原始模块清单

以下内容来自 PRD 内嵌电子表格的完整 `A1:B7` 区域：

| 模块 | 原始要求 |
| --- | --- |
| 首页 | 提供“创建游戏”入口和规则介绍入口 |
| 创建游戏 | 输入人数、选择阵容、录入玩家昵称、生成座位圆桌图 |
| 游戏记录 | 记录站队/身份推测标签、车型、远征投票结果和组队投票结果 |
| 概率计算 | 展示每位玩家的嫌疑度；可按不同阵容设置先验概率；具体算法暂缓，界面先预留展示位置 |
| 历史记录 | 保存每局结果、统计每位玩家胜率、评选 MVP |
| 数据存储 | 使用本地存储，暂不支持云端同步 |

这张表说明概率分析虽然属于早期产品愿景，但 PRD 当时并未要求在第一阶段确定计算方法，只要求预留展示位置。因此，后续实现概率功能应作为新阶段重新定义指标、算法和验证方式，而不是把某套未经确认的算法视为遗留验收项。

## 需求演变

| 需求主题 | 早期设想 | 第一阶段最终处理 |
| --- | --- | --- |
| 玩家标识 | 录入全部昵称 | MVP 主要使用座位编号；自定义昵称未作为交付前置条件 |
| 投票记录 | 区分远征投票与组队投票 | 当前只实现一轮组队表决 |
| 数据保存 | 曾讨论本地或云端 | 对局状态保存在浏览器 `localStorage`，没有业务后端数据库 |
| 概率分析 | 自动计算嫌疑度和先验概率 | 未进入第一阶段 MVP，作为后续产品方向 |
| 历史与战绩 | 历史记录、胜率与 MVP | 实现单局任务/发车回顾；长期账号战绩未进入第一阶段 |
| 身份推理 | 标签、笔记、可能的共享笔记 | 实现本地身份标签与自由笔记；没有联机共享 |
| 规则与结束 | 三次任务胜利、连续否决、刺杀 | 已建模主要规则，并加入刺杀流程与特殊任务规则 |

## 对“完成”的定义

第一阶段完成不代表原始想法全部实现，而代表：

- 核心对局路径可以从开始走到结束；
- 主要规则可以被系统记录和判定；
- 关键状态能够在本地保存；
- 基础使用说明、测试记录和部署资料可供下一位维护者理解；
- 未完成的想法被明确写成范围边界或后续 Issue，而不是隐性承诺。

当前实现的详细功能及两项已接受的 PRD 差异，以仓库根目录 [`README.md`](../../README.md) 为准。

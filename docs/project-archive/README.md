# Avalon Companion 项目档案

本目录是从团队原飞书工作区整理出的项目历史，用于在飞书组织停用后继续保留决策背景、测试证据和交接信息。资料于 2026 年 8 月 13 日归档，已去除重复上传的附件，并将分散的会议记录合并为可维护的 Markdown 文档。

迁移时已读取项目启动文档、PRD 正文及其内嵌模块表、2026-06-24 至 2026-07-13 的五份周会记录，以及 21 条 MVP 测试用例。PRD 模块表共有 7 行、2 列，已完整归档到[原始需求与范围变化](02-original-requirements.md)。

## 如何使用这套档案

- 想知道项目为什么开始、成员与角色如何确定：读[项目起点与团队机制](01-origin-and-team.md)。
- 想比较最初设想和最终 MVP：读[原始需求与范围变化](02-original-requirements.md)。
- 想追踪重要产品决定的形成过程：读[会议决策时间线](03-meeting-timeline.md)。
- 想知道第一轮可用性/功能测试发现了什么：读[MVP 测试记录](04-mvp-test-record.md)。
- 想接手维护或启动下一阶段：读[项目复盘与维护交接](05-retrospective-and-handover.md)。

## 权威性边界

这些文件记录的是项目在特定时间点的事实，不是新的产品承诺：

1. 当前实现、运行方法和已知范围边界以仓库根目录的 [`README.md`](../../README.md) 与 `main` 分支代码为准。
2. 原始 PRD 是立项时的目标；其中部分内容后来被调整、延期或替代。
3. 测试结果是执行测试当日的快照；后续修复不能反向改变历史结果。
4. 后续需求应创建 GitHub Issue，经维护者确认后再进入开发。
